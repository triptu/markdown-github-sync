# GitHub Vault Sync 0.3.0-beta.3

Setup discovers the repository and upstream branch from an ordinary local Git checkout. Tokens use a masked text box with automatic read-access checks and a copyable creation URL. Replacements are verified before saving, preserve the working token on failure, and use an independent secret key. Late results for previous settings are ignored.

The connected settings page shows current status, last successful sync and last verified access beside Sync now and History. Sync now handles both directions. Saved edits still trigger prompt sync; idle foreground checks run every five minutes. Repository read access does not by itself prove permission to publish commits.

The download client reuses local bytes only after matching their Git blob identity and size, so existing vaults and restarted devices fetch just the missing versions. Large initial downloads use a commit-pinned ZIP; small deltas use up to four concurrent blob reads. The GitHub tree remains authoritative, including scope, modes and hashes. An archive never writes directly to the vault. Missing or transformed archive entries fall back to individual blob downloads. The latest verified snapshot stays available even when its encoded contents exceed the general object-cache budget.

Read-only acceptance against the actual private repository returned 652 files with byte-identical snapshots through both download paths. Existing-vault loading used six requests, including two blob reads and no ZIP. The next unchanged-head check used one request and no file downloads. A cold snapshot used five requests: commit, tree, root ignore file, archive request and redirect. There were no errors or writes. These are request counts from a Node transport acceptance run, not Android latency measurements. Evidence: [download acceptance](../verification/github-downloads-beta3.json); rerun with `./plugin/node_modules/.bin/tsx scripts/github-download-check.ts`.

Validation: all 527 plugin tests pass, TypeScript checking and the browser bundle/package build pass, and an independent Opus review found no blockers. The installed build was loaded in the existing macOS Obsidian vault and the five-minute interval, connected status and Sync now controls were inspected. The new archive path has real GitHub acceptance through a Node transport; this release's new UI/archive path has not received a fresh Android device run.

Previous secret-storage keys are retained when a token is replaced, because another vault may still refer to one. They can be removed in Obsidian's Keychain when no longer used.

The publication protocol and prior documented editor/storage limitations are unchanged. This release changes retrieval and settings, not the synchronization conflict or publication model.

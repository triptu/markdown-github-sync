# Native E2-2 / E2-3 engine-facing port (R3)

Scope: native worker changes only `obsidian-vault.ts`, `native-transactions.ts`, native tests. Engine worker owns session/reconcile/contracts and must reconcile stale hold IDs; this note is the interface agreement, not a contracts edit.

1. `recover({replay,cancel})` remains the sole authorization for native pending intents. When a pending intent's visible source is oversized, native will durably retain `NativeIssue.kind="oversize"` with `sourcePath === path`, size/mtime, expected/next; leave both visible file and hidden preimage untouched; keep the intent pending for both replay and cancel. It returns normally, so other paths can progress. `pendingIntents()` continues to report that intent. `scan()` independently reports the visible file as unreadable. `apply()` on that path blocks while the issue or intent remains.
2. Existing hidden oversize sources use `sourcePath` under hold/stage. A tracked source that changes from oversize to readable or missing produces a new durable byte issue with the same path/sourcePath and `found` equal to its exact readable Entry or `null` for missing. The journal atomically supersedes the stale oversize record with the new issue; it never deletes the source. New readable bytes are pinned before the old metadata retires. A source that changes to another oversized version gets a new oversize ID as before.
3. Native IDs are version evidence. An old oversize ID removed by supersession must not remain a valid user decision or be silently acknowledged by the engine. Reconcile the current native issue set with durable engine holds/decisions, preserving original base and newly pinned byte evidence. Revalidate consent when source evidence changes. For a missing hidden source, the new found:null issue is the durable fact of absence; do not require the old size/mtime for ack. An unchanged oversize source retains its ID, export and ack flow.
4. Suggested optional LocalVault surface if engine needs it: a read-only current recovery listing is already available on GitObsidianVault as `nativeRecoveries()`; native's normal `recover()` returns all current records. No new required contract method is planned. No hidden source deletion is implemented.
5. Other engine safety remains engine-owned: unreadable visible paths with holds must not become absent/mine deletion, resumed apply must not infer absent from unreadable, and quarantine must guard persisted operations.

This port will be updated if implementation details change. Native acceptance uses fake in-memory host and durable journal crash injection; no real vault/device/remote writes.

## Final native details

The native journal also detects transitions **after** an oversize ID was acknowledged: acknowledged oversized source -> readable or missing creates a fresh byte/missing issue, including when readable bytes equal the old preimage. A tracked missing hidden source stays tracked; if it reappears, its bytes become fresh evidence even after the missing issue was acknowledged. Superseded issue IDs are recorded durably and rejected by `acknowledgeRecovery`; repeated acknowledgement of an actually acknowledged current ID remains idempotent. This preserves consent versioning through export/ack/source changes and through a crash before or after the journal's final-record rename.

No optional LocalVault method is required. `NativeIssue` already supports `kind="oversize"` with visible `sourcePath===path` and byte issues with `found:null`. The native implementation does not change session/contracts. Engine must continue to treat these changing IDs as new evidence and invalidate prior choice IDs; the native journal cannot itself edit durable engine holds.

A pending replay/cancel also catches a visible file growing past 8 MiB between the initial check and a later hash read. It persists the same path-local evidence and leaves the intent pending; unrelated paths remain available. Native focused tests cover this late growth for both authorizations.

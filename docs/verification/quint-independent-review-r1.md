## Findings

### F1 — Moderate: native handoff prose claims durable issue contents that its state does not model

`formal/quint/nativeHandoff.qnt:5-9,28-32,42-48,87-91` stores `kind` and `found` in one global state, adds the found value to global `recovery` during `nativeEffect`, and makes `ingest` change only `ready`, `recorded`, and `engineIssue`. `ackBacked` requires just the boolean `recorded`; `evidenceRetained` checks the global set that was filled **before** ingestion. After `acknowledge`, the model keeps the global `kind`/`found` even though `nativeIssue` is cleared. There is no separate durable engine record of issue ID, kind, found bytes, or hold contents, nor a transition that copies them before native acknowledgment. A broken implementation that saves a hold flag but loses the issue bytes can satisfy these invariants. This is a coverage hole, not a discovered current implementation failure.

`docs/verification/quint.md:70` says the model's ingestion persists kind, retained bytes, and path hold and that crashes retain both native and engine records. Narrow that statement to the modeled flag/hold ordering, or extend the model with native and engine data stores, acknowledgment disposal, and a preservation invariant. The current TypeScript boundary at `plugin/src/git-sync/session.ts:1046-1078` does verify and pin entries and save the hold before acknowledgment; the model does not formally establish that implementation property. The page's caveat at line 74 already admits that storage retention and actual handoff are not proved, but it does not remove the stronger line 70 claim.

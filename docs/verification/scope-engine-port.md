## Factory handshake for root UI (critical)

`GitHubRepository` has an immutable `scopeRules`. Engine `#readHead` and immutable `readCommit` verification **do filter** a config/1 repository's snapshots down to a stored visible-only session scope, so they do not rewrite a /3 base with hidden files. However, repository `prepare()` uses the adapter's own immutable mode. Therefore **do not run an existing visible-only enrollment's normal sync with a config/1 repository**: a candidate-side `.gitignore` can make the adapter reject an otherwise legacy-visible publication. Construct the normal repository from the persisted enrollment mode (`visible-only` for /3 migration), not from a new settings toggle.

For migration review only, root may construct a **temporary config/1 repository and SyncSession using the same durable store**, call `previewConfigurationScope()` then `enableConfigurationScope({token})`, and dispose that session without normal sync. `enable` persists only `pause.reason="scope-enrollment"` after exact review; it does not reinterpret the old base. Once it returns `reenroll`, construct the config/1 repository/session and call existing `previewEnrollment()` then `enroll({token})`. Persist the setting as config/1 only after `reenroll` succeeds. On crash before that settings save, startup must detect durable `scope-enrollment` pause and choose the config/1 repository for reenrollment; never perform a normal sync under the mismatched adapter. Fresh config/1 enrollment is selected before `previewEnrollment()` and still requires its explicit enrollment token. A settled visible-only enrollment with no migration marker always uses a visible-only repository/session.

The UI may use `listConfiguration()`, `previewApplyConfiguration()`/`applyConfiguration({token})`, and `previewHiddenPublication(path)`/`consentHiddenPublication({path,token})` after native `scan(scope)` is wired. They return reviewed exact-version state and do not reload the host. All incoming `.obsidian/**` stays deferred.

Step 1 of 7

You save a note

The original stays in your laptop’s vault. This plugin does not encrypt local files at rest.

What the cloud receives

Encrypted file envelopes, opaque file IDs, revision numbers, sizes, server timestamps and deletion flags.

What stays private from the cloud

Your note contents, original paths and encryption key. The server access token is separate from the key.

What we’ve done

  • ✓Inspected Obsidian 1.14.4’s shipped sync code; recorded findings and evidence limits.
  • ✓Built the plugin, encrypted protocol, conflict copies and version recovery.
  • ✓Tested client + server together in Cloudflare’s local runtime; packaged plugin ZIP.
  • ✓Pushed private repo and registered the project in T3.

What makes it live

  • ○Provision Cloudflare resources and set the server access token.
  • ○Deploy the Worker and obtain its HTTPS URL.
  • ○Install the plugin on your devices and transfer the private setup code.
  • ○Verify desktop + phone behavior using a copied vault.

Current scope: files ≤ 8 MiB · foreground mobile sync · no settings/plugin sync · conflict copies, not automatic text merges.

Deployment tooling and verification boundaries

Wrangler currently packages and deploys the server. Its dry run passed; it created no live resources. Alchemy has not been implemented. Changing that deployment layer does not change the plugin’s sync protocol.

25 tests means 21 plugin/adapter tests and 4 server/integration tests. No live Obsidian or physical phone test has been run. Obsidian’s binary-write and trash APIs also leave a narrow race with simultaneous external file edits.

Remote history is retained indefinitely; costs grow with revisions. This is a personal server with a shared token, not a multi-user permission system.

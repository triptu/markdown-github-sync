The plugin compares what you last synced, what you changed, and what’s now on GitHub. It publishes a new commit only when those versions agree—or you resolve the difference.

The phone keeps your files and a recovery journal, and uses GitHub’s API instead of maintaining a local Git database.

Content synced

The branch update is the publishing moment. Uploading files or saving a local note alone never counts as “synced.”

Under the hood: one publication path

blobs → tree → commit → conditional branch update

REST uploads objects in bounded requests. GraphQL updateRefs(beforeOid) advances the branch only from the expected commit. A rejected or uncertain response triggers reconciliation, never a force push. The pending commit ID is saved before publication.

The tradeoffs, plainly.

Notes remain readable in your private GitHub repo, as they are today. This gives up the previous prototype’s end-to-end encryption.

One sync owner per active vault. Other Git clients can still use separate checkouts. Phone syncing runs while Obsidian is active; background delivery is not promised.

Content first. The 79 tracked Obsidian configuration files stay untouched on GitHub; settings sync needs its own explicit scope.

Tested at the API.
Not yet trusted with your vault.

We created a private test repository containing only synthetic files. Your real vault and current Obsidian Git installation were left untouched.

The work that still matters

Native phone storage, crash recovery, editor races, and low-disk behavior are not validated.

A journal does not make binary replacement atomic. We need a demonstrated apply strategy before enabling those writes automatically.

Fine-grained token permissions, repository rules, and mobile memory limits still need testing.

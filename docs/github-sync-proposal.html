What happens when you write?

Choose a situation. The examples are synthetic. They show the implemented sync path and the configuration behavior still under review.

01 / 05

Two devices edit different files

The laptop changes one note; the phone changes another. Both start from the same committed version.

Both edits can join the history.
  1. LOCAL

    Each saved edit is a draft on its own device.

  2. GITHUB

    The first accepted commit moves the branch; the next device compares that new head before publishing.

  3. OTHER DEVICES

    Sequential, independent edits converge. A truly simultaneous publication can pause for reviewed recovery.

Automatic sync runs after saved edits, on foreground return, and periodically while Obsidian is open. “Sync now” is also available.

The branch says what.
The ledger says whether.

One plugin runs inside Obsidian on each device. It has no local Git database and no Cloudflare service in the publication path.

1

Capture a local draft

The plugin reads eligible saved files against its last accepted checkpoint. A per-vault queue keeps one active writer in this Obsidian host.

It compares base, draft, and current GitHub head. Immutable file objects, a tree, and a candidate commit are prepared before anything becomes shared.

Publish atomically

The branch moves only from the expected parent, together with this installation’s ledger receipt. A rival publisher cannot silently replace the accepted commit.

Apply with recovery

The receiving device protects original bytes in a native preimage hold, applies the accepted version, and advances its checkpoint only after accounting for each path.

Uncertain response? The client reads the ledger. A matching receipt means the candidate was accepted; its own seal means that attempt was cancelled. If the result cannot be established safely, sync pauses for review. It never blindly replays the old candidate.

Safety lives at each boundary.

These are specific implementation mechanisms. They narrow failure modes; final device acceptance still matters.

01 / Local writes

Keep the bytes that came before.

A native preimage hold and durable journal protect an existing file before replacement or deletion. Interrupted operations resume or remain held; recovery export preserves captured bytes.

02 / Ownership

One active writer in this host.

Queued operations fence retired plugin instances, local events, and stale previews. A separately copied installation identity triggers a duplicate-installation pause.

03 / Scope

Only eligible paths enter the plan.

Built-in private paths and recovery files stay out. Committed ignore rules are checked before reading excluded file bytes. Unreadable or unexpectedly missing content cannot stand in for deletion intent.

04 / Restore

History returns as a draft.

Pick a file and a GitHub commit, preview the historical version, then restore it locally. A later normal publication makes a new commit; the shared branch is not rewound.

Configuration takes a separate door.

Notes and attachments are the ordinary sync path. Configuration needs an explicit scope upgrade and review. Existing configuration on GitHub stays preserved while outside scope.

New hidden configuration files need exact consent before publication. Incoming live configuration is deferred for review. The composed review found migration, stale-writer, and status-reporting defects in this new path; its fixes and Android acceptance remain open.

Recommended

GitHub API client

Phone files → plugin → GitHub commits

No local .git database. Upload file objects in bounded requests, then publish the whole commit with an exact branch-head check. Local journaling and conflict handling remain our responsibility.

Full Git in JavaScript

Phone files → local Git database → GitHub

Offline commits, local history, other Git hosts. More packfile, index, memory, and recovery work. Obsidian Git already uses this approach on mobile; switching libraries alone does not solve reliability.

Keep a Cloudflare service

Phone files → custom service → GitHub

Could add notifications later. Adds hosting and another failure boundary without removing the need for accepted GitHub commits. No current requirement justifies it.

Two ways to publish through GitHub’s API

Preferred: upload blobs and a tree, create the commit, then use updateRefs(beforeOid). Individual uploads resume independently; one branch move publishes the full batch.

Simpler alternative: createCommitOnBranch sends every changed file in one request. We tested it successfully, but large batches require more buffered memory and it has no explicit file-mode control.

One production write path, not automatic fallback to weaker concurrency checks. Fine-grained-token compatibility remains a release gate.

GitHub stores readable notes, just as your current private repo does. This replaces the earlier encrypted Cloudflare design. The active vault has one sync owner; other Git checkouts can still publish to GitHub separately.

Manual sync, conflict decisions, history restore, then optional automatic commits.

Cut over with a rollback copy
Fresh plugin-owned vault from GitHub. Disable the old plugin before the new one writes; remove it after device verification.
